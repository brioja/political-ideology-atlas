# Political Ideology Atlas

A political ideology test where the axes come from the data. You don't choose them in advance.

## How it works

1. `data.js` has 40 statements and 19 reference ideologies. Each ideology is written as its
   expected answer (-2..+2) to every statement.
2. `pca.js` centers that 19 × 40 matrix, builds the 40 × 40 covariance matrix, and
   eigendecomposes it (Jacobi method, no dependencies). Each eigenvector is an axis. Its
   eigenvalue is how much of the disagreement between ideologies that axis captures.
3. The model keeps the fewest axes that explain ≥ 80% of the variance (currently 3: social
   traditional↔progressive, economic state↔market, and state↔anti-state). Change
   `varianceTarget` in `buildModel` to keep more or fewer.
4. Your answers are projected onto those axes. Ideologies are ranked by distance in that space.
   The results show the top matches, flag close calls, and list the statements where you agree
   and disagree with your top match.

Adding a statement or an ideology means adding one string to `data.js`. The axes, their names,
and the number kept all update on their own.

## Sharing results

The results page has a share link (`?r=1.` followed by one character per statement) that reopens
the same results for anyone, and a downloadable 1200×630 image.
Nothing is stored on a server. `og.png` is the preview image for links to the home page; it is
generated by `drawCard` with no result.

If you change the statements, bump the `1.` version in `encodeAnswers`/`decodeAnswers` so old
links don't decode against the wrong questions.

## Ideology audits

Each ideology in `audits/catalog.json` gets a sourced audit at `audits/profiles/<id>.json`:
its answer to every statement with a rationale, confidence and citations, plus a Wikipedia link
and further reading. `audits/PROMPT.md` holds the exact research instructions, so any audit can
be re-run.

- `node scripts/pending.js` lists ideologies whose audit is missing, stale or invalid.
- `node scripts/validate.js [id ...] [--links]` checks audits (add `--links` to test every URL).
- `node scripts/build.js` compiles valid audits into `data.js` (`--status` just reports progress).
- `node scripts/wikipedia.js` refreshes suggested Wikipedia links in the catalog.

To run every pending audit, ask Claude Code to "run the ideology-audits workflow"
(`.claude/workflows/ideology-audits.js`). It costs roughly 75k tokens per ideology and is safe to
stop and resume, since finished audits are skipped. Pass `{"limit": 10}` to do a batch. Changing
`statements.json` marks every audit stale.

## People

`audits/people-catalog.json` lists about 270 public figures chosen for balance across gender,
region, era and the political spectrum (`node scripts/people-report.js` prints the mix). Each gets
an audit at `audits/people/<id>.json` following `audits/PROMPT_PEOPLE.md`: positions come from the
person's own words and record, and a statement with no reliable evidence is `null` instead of a guess.

- **Salience:** a person is included only if their recorded positions place them on the test's
  dividing lines at least as precisely as a typical test-taker is placed when their own result
  settles (median of simulated test-takers; Bayesian placement uncertainty, see `salienceContext`
  in `pca.js`). People and test-takers are compared, so both should rest on similar evidence.
  It depends on which statements have a recorded position, not on the answers, and has no
  hand-picked cut-off. Negative controls (`audits/controls/`, apolitical celebrities audited with
  the same instructions) must fail it; `node test.js` checks this. Excluded audits make the
  validator exit with code 2 so they aren't re-audited.
- **Tie-break:** when two people are within 3 points of each other, the one with more English
  Wikipedia page views (last 12 months, from `node scripts/pageviews.js`) ranks first. The counts
  are stored in the catalog; the site never calls Wikipedia.
- To run the audits, ask Claude Code to "run the people-audits workflow" (about 75k tokens per person).

## Run locally

Open `index.html` in a browser, or run `python3 -m http.server` and visit http://localhost:8000.

`node test.js` checks the eigensolver and verifies that every ideology matches itself. It also
prints the axes it found.

## Deploying

It is a static site with no build step and no server, so any static host works:

- **GitHub Pages:** push this folder to a repo, then turn on Settings → Pages → deploy from branch.
- **Netlify / Cloudflare Pages:** drag the folder in, or connect the repo. There is no build
  command and the publish directory is `/`.

## Next step: axes from real people

Right now PCA runs over the 19 ideology profiles, which I wrote by hand, so the axes reflect
those judgments. The stronger version runs PCA over actual respondents' answers. To get there
you need somewhere to store responses (a small database or form backend). After a few hundred
responses, you can recompute the axes from those people and match against ideology profiles
projected into the same space.
